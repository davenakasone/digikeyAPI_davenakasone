## 2. DigiKey Developer Portal Realities

### A. App Creation Checklist
When registering an App in the [DigiKey Developer Portal](https://developer.digikey.com/):
1. **Organization:** Must be under an Organization (e.g. `davenakasone`).
2. **Environment:** Production vs. Sandbox. (For real part queries and stock numbers, use a Production App).
3. **OAuth Callback URL:** Set to `https://localhost` (or `https://127.0.0.1`). Required by the portal even if primarily using 2-legged OAuth.

### B. API Product Permissions & Gating
| API Product | Self-Service? | Notes |
| :--- | :---: | :--- |

## 3. OAuth 2.0 Realities & Authentication Flow

### Flow Decision: 2-Legged vs. 3-Legged OAuth

1. **2-Legged OAuth (`grant_type=client_credentials`) — Recommended Default for Package Search & Data Retrieval**
   - **Endpoint:** `POST https://api.digikey.com/v1/oauth2/token`
   - **Headers:** `Content-Type: application/x-www-form-urlencoded`
   - **Body:** `client_id=...&client_secret=...&grant_type=client_credentials`
   - **Characteristics:**
     - Requires **NO browser login, NO user redirect, and NO manual interaction**.
     - Returns a Bearer `access_token` with `expires_in: 599` (approx 10 minutes) or `1800` (30 minutes).
     - Fully sufficient for all Product Information V4 searches, pricing checks, category lookups, and datasheets.

2. **3-Legged OAuth (`grant_type=authorization_code`) — User-Specific Operations Only**
   - **Use Case:** Only required if accessing a private user account's custom order history, credit ordering, or proprietary quote locks.
   - **Auth Code Lifespan:** Authorization codes expire in ~60 seconds and are strictly single-use. Any reuse returns:
     `{"ErrorMessage":"Invalid authCode","ErrorDetails":"Get new authCode"}`.
   - **Refresh Token Lifespan:** ~90 days.

## 4. Key Troubleshooting Traps & Resolutions

### Trap 1: Sandbox Egress Policy Error
- **Symptom:** `403 Forbidden: Request to POST /v1/oauth2/token on api.digikey.com not allowed by policy`
- **Root Cause:** When running commands inside isolated AI assistant / sandbox environments, outgoing network connections are blocked by default unless network access / sandbox bypass is permitted.
- **Resolution:** Run network scripts with proper network execution permissions. The error string was generated by the environment proxy, not DigiKey's servers.

### Trap 2: Missing `X-DIGIKEY-Client-Id` Header
- **Symptom:** API endpoints return `401 Unauthorized` or `403 Forbidden` even with a valid `Authorization: Bearer <access_token>` header.
- **Root Cause:** DigiKey API Gateway strictly requires **BOTH** the Bearer token AND the `X-DIGIKEY-Client-Id` header on every single REST call.
- **Resolution:** Always construct API request headers as:
  ```python
  headers = {
      "Authorization": f"Bearer {access_token}",
      "X-DIGIKEY-Client-Id": client_id,
      "Content-Type": "application/json",
      "Accept": "application/json",
  }
  ```

### Trap 3: Token Expiration Handling
- **Symptom:** Scripts run fine initially, but fail after 10–30 minutes with `401 Unauthorized`.
- **Root Cause:** Tokens expire quickly (typically 600s / 10 min for 2-legged).
- **Resolution:** Implement proactive token caching in the client wrapper:
  ```python
  if now < self._token_expiry - 60:
      return self._cached_token
  # Otherwise, request a new token before making the API call
  ```

## 5. Architectural Roadmap for General DigiKey Python Package

When expanding this into a full general-purpose DigiKey client library:

```text
digikey/
├── __init__.py            # Package root exports (Client, Exceptions, Models)
├── auth/
│   ├── __init__.py
│   ├── oauth2.py          # 2-legged & 3-legged OAuth managers, token cache
│   └── credentials.py     # Hierarchical credential resolver (Vault -> .env -> env vars)
├── client.py              # Main DigiKey client entrypoint
├── services/
│   ├── __init__.py
│   ├── products.py        # Product Information V4 (search, details, pricing)
│   ├── categories.py      # Category taxonomy & parameters
│   ├── barcode.py         # 2D DataMatrix barcode parsing
│   └── orders.py          # Order status & tracking
├── models/
│   ├── __init__.py
│   ├── product.py         # Pydantic / Dataclass models for typed responses
│   └── pricing.py         # Price break data structures
└── exceptions.py          # Custom DigiKeyAPIError, AuthenticationError, RateLimitError
```

### Key Package Design Principles:
1. **Zero-Friction Auth:** Initialize `DigiKey()` without arguments, and it automatically discovers credentials from the vault or environment.
2. **Automatic Refresh:** Never expose raw token management to the consumer unless they ask for it.
3. **Structured Outputs:** Return typed dataclasses or Pydantic models alongside raw JSON for ease of use.
4. **Rate Limit & Retry:** Built-in exponential backoff for `429 Too Many Requests`.

## 6. Live Endpoint Discoveries & PCB Sourcing Workflows

### Exact DigiKey V4 Production Endpoints:
- `POST /products/v4/search/keyword`: Primary search handler for all general keywords, MPNs, and DKPNs.
  - Supports filter payload: `{"Filters": {"InStock": true, "TaxonomyIds": [cat_id], "ManufacturerIds": [mfg_id]}}`.
  - Supports sort payload: `{"Sort": {"SortBy": "UnitPrice"}}`.
- `GET /products/v4/search/{productNumber}/productdetails`: Universal details endpoint. Resolves BOTH Manufacturer Part Numbers and DigiKey Part Numbers.
  - Returns `Parameters` with `ParameterText` and `ValueText`.
  - Returns `ProductVariations` array containing package-specific `DigiKeyProductNumber` and `StandardPricing`.
  - Returns direct `DatasheetUrl` (or `PrimaryDatasheet`) and `PhotoUrl`.
- `GET /products/v4/search/categories` & `GET /products/v4/search/categories/{id}`: Category taxonomy and nested children.
- `GET /products/v4/search/manufacturers`: Complete list of 3,714 authorized manufacturers.

### PCB Design & BOM Workflow Integration:
- CLI command `python -m digikey bom <path_to_bom.csv>` automatically parses EDA schematic BOM exports (KiCad, Altium, Eagle).
- Checks stock status (`Active`, `InStock`), attaches DigiKey part numbers, computes tiered batch production costs, and downloads manufacturer datasheet links.
